
Problem Statement
> Periodontal charting requires measuring ~192 pocket depths (6 sites × 32 teeth) plus bleeding, recession, and mobility. The hygienist has both hands occupied inside the patient’s mouth (mirror and probe).
> A typical periodontist’s office involves a trained assistant continually listening to the practitioner for cues as him/her performs the examination.
> In the absence of the assistant, the hygienist probes a few teeth, stops, degloves or touches a dirty keyboard/mouse, types the numbers, and returns to the patient, creating cross-contamination risk & miserable UX.
> This is a manual pipeline that can be automated to a large extent, with minimal compute and high levels of accuracy, this allowing the trained assistant to engage with more productive levels of work at the office


Solution - PerioVoice
> Introducing PerioVoice, a local solution involving a STT on device model, that runs on the browser, be it on the PC or mobile, automating the above pipeline with JSON exports for easier integration with existing PMS whilst eliminating cloud dependency.
> The architecture pairs a WebAssemby-based speech recognizer with a custom JS parser, constrained by a strict clinical grammar. 
> This achieves mic-to-pixels with zero network hops — decode plus parse
> run in tens of milliseconds on office hardware, inside a sub-300ms
> end-to-end budget verified per-machine (see EVAL.md) — while driving
> ongoing inference and hosting costs to absolute zero.

Solution - DeepDive
• pnpm is used for package management.
 • The live app is 100% JavaScript/WASM in the browser; Python is used only for testing harnesses.
 • A wrapper (recognizer.js) streams mic audio to an on-device Vosk WASM engine, which emits partial and final transcripts. Partials drive a live UI preview; finals are sent to the parser.
 • The STT engine is hard-constrained by grammar.json. This acts as a Grammar-FST, dropping all non-clinical words from the search space to drastically reduce hallucination and improve accuracy.
 • A rule-based parser (perio.js) processes the text, updates the chart state in-place, and handles undo/corrections.
 • Listening is toggled via the UI or the Space bar.
 • The final chart is exported as a local JSON file.





Why this solution?
1. Frees the Assistant for Higher-Value Care - Lets the hygienist chart a full mouth hands-free (designed for under 3 minutes) without stopping to de-glove and type, giving an est. ~$25/hr of assistant time back per session for actual patient care (est.: loaded assistant wage × scribe minutes saved).
  2. Absolute Data Privacy (Zero HIPAA Liability) - Audio never leaves the device. Because the WASM speech engine runs entirely in the browser, there is no cloud transmission, no server storage, and zero breach surface.
  3. Zero Ongoing Compute Costs - Bypasses an est. ~$3,100/year per practice in cloud API fees (est.: per-minute STT pricing × charting volume, plus hosting) by doing 100% of the computation locally on the dentist's existing hardware.
  4. Instantaneous Feedback - Decode plus parse run in tens of milliseconds with no network roundtrip by design (no cloud baseline measured — the structural advantage is the absence of the hop, not a multiple). The numbers appear visually as fast as the hygienist speaks them; full-utterance budget is sub-300ms, verified per-machine (see EVAL.md).
  5. Near-Perfect Accuracy via Grammar Constraints - Instead of relying on slow, hallucination-prone LLMs, it uses a hard-gated Kaldi Grammar-FST. If a word isn't in the clinical vocabulary, it physically cannot be transcribed — parser 99.8% on ground-truth transcripts, ~86% digit accuracy end-to-end on synthetic speech (see EVAL.md for method; live-user validation still open).
